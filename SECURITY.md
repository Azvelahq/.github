# Security policy

Azvela welcomes responsible reports of vulnerabilities affecting its published repositories and software. Security and privacy are engineering responsibilities, not marketing claims.

## Scope and supported versions

Consult the affected repository's security policy, release notes and support information for its maintained versions. This organization-wide policy does not establish a universal support period or a guarantee that all historical releases receive patches. Report uncertainty about affected versions as part of your submission.

## Report privately

For a public Azvela repository with private vulnerability reporting enabled, open its **Security** tab, select **Advisories**, then **Report a vulnerability**. For an organization-level concern, use the [private reporting entry point for this repository](https://github.com/Azvelahq/.github/security/advisories/new) if available to you.

If private reporting is unavailable, consult the affected project's documented security contact. If none is published, open a [contact-only request](https://github.com/Azvelahq/.github/issues/new?template=contact_request.yml) asking for a private reporting channel. Do not include vulnerability details, proof of concept, credentials, personal data, or affected private resources in a public issue or pull request. Wait for a private channel before sharing sensitive information.

## What helps us investigate

- Affected project, version or commit and a concise summary.
- Preconditions, reproducible steps using a controlled environment, and observed versus expected behavior.
- Potential impact and relevant non-sensitive evidence; redact tokens, personal data and unrelated details.
- Suggested mitigation, if known, and any disclosure constraints.

## Responsible research

Limit testing to systems and data you own or are explicitly authorized to test. Avoid accessing other people's data, disruption, persistence, destructive actions and further exploitation beyond what is necessary to establish the issue. Stop if you encounter sensitive information; report it privately without copying or distributing it. This policy is not blanket permission to test Azvela systems, a legal safe harbor or a bug bounty offer.

## Handling and disclosure

Our intended process is to assess scope, reproduce where safe, prioritize impact, coordinate remediation, and agree on responsible disclosure as appropriate. We aim to communicate through the private report when possible. There is no published guaranteed response or remediation deadline. Recognition, when appropriate, requires the reporter's consent. Do not publicly disclose sensitive details before coordination; obligations under applicable law remain unaffected.

For ordinary defects or questions, see [Support](https://github.com/Azvelahq/.github/blob/main/SUPPORT.md). For AI-specific security concerns, use the same private route; do not post unsafe payloads publicly.
