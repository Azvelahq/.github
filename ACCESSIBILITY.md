# Accessibility

Azvela aims to design technology that can be used by people with different abilities, devices and circumstances. Accessibility is a product quality requirement, not an optional finishing step.

Our design direction includes keyboard and assistive-technology support, readable contrast, scalable text, reduced-motion alternatives, clear focus and error states, and understandable navigation. WCAG 2.2 is a useful reference for web experiences; this statement does not claim conformance or completion of an accessibility audit.

## Report a barrier

Use the affected project's accessibility issue template when available, or its documented support route. Include the platform, relevant version, assistive technology if applicable, steps to reproduce, expected behavior and observed barrier. Sharing a diagnosis is not necessary. Remove personal information from screenshots and recordings.

If the report involves privacy or security, use the [private reporting process](https://github.com/Azvelahq/.github/blob/main/SECURITY.md) instead. We prioritize barriers by impact and context; no universal resolution deadline is promised.
