# Contributing to Azvela

We value precise, thoughtful work. Contributions are welcome where a repository explicitly accepts them and grants the necessary license or permission. Read its README and local contribution rules first.

## Before writing code

Confirm the problem, scope and expected behavior. Check existing issues and propose substantial changes before investing significant effort. Do not assume this public repository grants access to private projects or permits reuse of proprietary materials.

## Make a reviewable change

Use a focused branch and a descriptive pull request. Keep unrelated refactors separate. Document behavior changes, migration risks and compatibility. Run the project's relevant tests, linters and security checks; report exact commands and outcomes, including failures or skipped checks. Add regression tests for defects when feasible.

## Evidence and AI-assisted work

Disclose material AI assistance when it affects review or provenance. Verify generated code, dependencies, citations and results yourself. Never submit confidential inputs to unauthorized services or include secrets, private data or unlicensed material. Do not claim tests were run unless they were run. An agent must not be the sole approver of its own changes.

## Review and acceptance

Maintainers may request changes, decline proposals or require more evidence. Passing CI is not a release authorization. Repository-specific licensing and contribution terms apply; if no license or permission is stated, obtain authorization before reuse or substantial code contributions. No blanket CLA or DCO is imposed by this file.

Report security issues privately using the [security policy](https://github.com/Azvelahq/.github/blob/main/SECURITY.md). Follow the [code of conduct](https://github.com/Azvelahq/.github/blob/main/CODE_OF_CONDUCT.md) in every interaction.
